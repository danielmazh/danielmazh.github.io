חזרה למה שהיה קשה
  1. 1 השרת בודק את המחשב וקורא את ~/.claude
  2. 2 עמוד הבית מראה את שורת המצב
  3. 3 פותחים את הסשן שצריך אותך
  4. 4 לחיצה אחת מחברת אותו מחדש או מחזירה אותו

הכלי כולו: השרת, העמוד, סקריפטי השמירה והשחזור ותוסף Chrome.

  • שרת Python של 1,990 שורות ועמוד יחיד של 2,406 שורות
  • 31 נתיבי API, רק הספרייה הסטנדרטית של Python
  • 2 סקריפטי zsh ל-watchdog ולשחזור, ועוד תוסף Chrome
  • אין בדיקות אוטומטיות. פעולות מסוכנות מציעות dry run במקום זה

מה זה עלה

המצב נקרא מטקסט במסך של ה-CLI ומרשימות תהליכים. זה לא דורש API, אבל ניסוח חדש ב-CLI יכול לשבור את הזיהוי.

  1. ל-Claude Code אין API לסשנים שרצים, אז העמוד צריך להבין את המצב שלהם מבחוץ.

    הוא מוצא מזהי סשן ברשימת ps, עולה עד 12 תהליכי אב כדי להגיע לחלון ה-tmux, וקורא את הטקסט בחלון כדי למצוא את הקישור לטלפון ודיאלוגים פתוחים. פרטי התמלילים נשמרים ב-cache לפי mtime וגודל, וחיפוש מלא מריץ grep -F במנות של 200 קבצים, כי זה מהיר יותר מפענוח JSON.

  2. שחזור אוטומטי יכול להזיק. הפעלה מחדש עלולה להרוג עבודה שרצה, ו-watchdog עלול להרים daemon שני או להיכנס ללולאה כשהרשת למטה.

    הפעלה מחדש שולחת /exit ומחכה עד 25 שניות. אם בחלון רצה עבודת רקע, היא מבטלת ושואלת אותי. ה-watchdog של launchd רץ כל 60 שניות עם נעילה, בודק פעמיים בהפרש של 10 שניות, לא עושה כלום כשה-API לא זמין, ומשאיר את החלון המת כדי שהלוג יראה למה הוא נפל.

Claude Control - README

מה זה שרת Python אחד ועמוד HTML אחד, בעברית ובאנגלית, רק עם הספרייה הסטנדרטית. יש בו שמונה עמודים: בית, סשנים ושחזור, חיפוש סשנים, לוגים, סשן חדש, ניהול, ניטור שימוש והוראות.

איך זה עובד השרת בודק את המחשב וקורא סשנים, הגדרות, skills ונתוני שימוש מתוך ~/.claude, ומגיש אותם ב-localhost. עמוד הבית מראה שורת מצב אחת עם כפתור שמתקן את מה שאפשר. לשאר הוא נותן פקודה להעתקה. אפשר לחבר מחדש סשן, לחפש בכל השיחות, להחזיר סשן שנעצר ולבנות חדש.

איך זה רץ סקריפט התקנה מוסיף אותו כ-launchd agent. עם דגל נוסף הוא מוסיף watchdog שמחזיק את ה-daemon לשליטה מרחוק, וסקריפט שמשחזר סשנים בכניסה למחשב. חלקים שאין במחשב מזוהים ולא מוצגים.
