One of my early full-stack projects, from 2022 to 2023. It began as a small Flask form and grew into a React and Node app.

Back to what was hard
  1. 1 Sign up and verify
  2. 2 Answer the questionnaire
  3. 3 Scoring ranks the wineries
  4. 4 Tours appear by area

Solo: client, API, database and the data model.

  • 196 commits in 9 days on the main repo, all mine, after 3 earlier repos
  • 3 tables, and the wineries table has 25 columns, 7 of them opening hours
  • 6 preference categories and 4 questionnaire pages
  • No real tests, only the default template test file

What it cost

Winery styles, attractions and wine types are comma-separated text. This kept the add form simple, but matching runs row by row in JavaScript instead of in SQL.

  1. A match has hard rules (area, budget, open at that hour on that weekday) and soft preferences that each user weighs differently.

    SQL removes what cannot work, using the opening-hours column for the chosen weekday. Each of the 6 categories then gets a score from 1 to 5, multiplied by the user's grade and divided by the maximum possible, so a skipped category does not lower a winery's rank.

  2. Profile pictures had to stay private, and the server did not know each file's extension.

    The server reads the user from the JWT, checks S3 for each possible extension, and returns a signed link that expires after 5 minutes.

Wineries IL README

What it is You sign up, verify your email, fill in a questionnaire on area, date, budget and style, and get tours grouped by area.

How it works A scoring function ranks wineries against your answers. Users can add wineries too.

How it runs A React client on an Express API with PostgreSQL. It was set up for Heroku and is no longer running.
