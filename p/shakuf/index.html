I owned all of it, then gave the talk with it.

  • About 40,000 lines of TypeScript, about 13,000 on the server, in one Node process
  • 2,542 tests passed in the last full run before the talk
  • 102 real model calls saved as JSON for replay
  • Load test on my laptop, October 14: 300 phones, every vote counted, p95 about 6 ms

What it cost

Model calls are not streamed, and live and recorded answers share one path. The cost: the room sees nothing of a round until its full answer arrives.

  1. A live model call can time out, fail or miss the point of the slide while the whole room waits.

    Each step has a call deadline, a step budget and a call cap. On failure the whole step reruns from the recording, then from sample data, so one step never mixes live and recorded calls. A badge on the stage says live or recorded, and the console says when a step fell back.

    The talk ran live on GPT-5.4, not in sample mode.

    In the diagram: Sample data

  2. The presenter can move on while a call is still running, and a late answer must not land on the wrong slide.

    Each run gets a number and an abort signal. Next aborts the HTTP call, and a result from an older run is dropped. Going back only shows saved results, so it never calls the model again.

  3. Stage, console and a room of phones must show the same step, even after a crash, a laptop sleep or a dead phone socket.

    The server owns the state. It pushes full views per role, at most once per tick, and saves to disk at most every 200 ms with an atomic rename. Phones also ping the server, because iOS can keep dead sockets open.

    A test stops the server mid-talk, starts it again and checks the same step and results, with no new model call.

    In the diagram: Talk state hub

  4. The talk shows raw requests on a projector, but the key, the endpoint and the deployment name must never appear.

    The gateway removes those exact strings from every result. A second check runs on every WebSocket frame and HTTP response, and blocks the whole message if a secret is still inside. Tests scan pages, frames and logs for fake secrets.

Shakuf Labs README

What it is One web system with the slides, a live lab and audience votes. Shakuf means transparent in Hebrew. I gave the talk with it live, in Hebrew, in October 2026. The talk has 43 steps and takes about 31 minutes.

How it works People scan a code in the lobby, and the phone wakes up only for the three votes. The presenter works from a console with the speaker notes, keyword hints and one run button. Each lab step runs by hand, live or from a recording, and real model calls show what was sent and what came back. A recap quiz follows the talk.

How it runs A Fastify server holds the talk state and pushes it over WebSocket to the stage, the presenter console and the phones. It runs from one laptop. A phone can only join and vote, so it can never change the talk. With recorded answers, the scripted steps go on with no key and no internet. A free question from the floor may get no answer.
